# Adopt 0.4.1 skill ownership

This is an instruction-routing update, not an Editor, package, schema or validation migration. Projects older than 0.4 must also complete the [lean migration](lean-0.4.0.md).

1. Inspect the installed kit, root/client instructions, custom task skills and selected-client OpenSpec integrations. Preserve working changes. Assess the candidate, preview/update managed files, then run installer check using [workflow updates](../workflow-updates.md). A managed-file conflict requires reconciliation, not force.
2. Adopt [skill ownership](../context-efficiency.md#skill-ownership) in project-owned instructions. Remove duplicate OpenSpec lifecycle tutorials and Unity command recipes after preserving unique project decisions, working commands and qualified compatibility exceptions. Keep README check entrypoints, actual automation scripts, tested examples and all validation gates. Do not create a second router or policy document.
3. Remove contradictory blanket promises of uninterrupted propose-to-apply execution. Generated operation boundaries apply, including planning-only stops. Keep kit policy in root rules/config/schema; never patch generated OpenSpec or downloaded Unity skills to bypass their instructions. Preserve customized integrations; repair missing selected-client integrations through reviewed OpenSpec setup, without upgrading pins implicitly.
4. Detect already-adopted behavior: one kit bootstrap orchestrator, operation-specific OpenSpec delegation, available Unity specialists for mechanics, no repeated intake for settled decisions, and a documented missing-provider fallback. Apply only missing compatible changes. No new dependency/plugin is required.
5. Review representative routes: existing active feature (apply), new proposal (honor its stop), custom UITK control (retain Builder/MVVM/navigation/visual checks), CLI operation (preserve project identity/pins), and a client without Unity plugins (help/versioned docs fallback). Validate links, generated integration discovery and the project's existing workflow checks. Source review is not a live-agent or Unity acceptance result.
6. Review the diff for deleted unique decisions or weakened gates. Roll back the migration commit/project-owned edits and restore the previous reviewed kit with the installer if necessary; preserve unrelated work. Historical evidence/receipts remain unchanged. Updating globals and migrating other games are separate actions.

No runner/template replacement, schema conversion or historical receipt refresh is needed for a project already on 0.4.0. This release reduces repeated procedure text; session-token savings require measurement in actual projects.

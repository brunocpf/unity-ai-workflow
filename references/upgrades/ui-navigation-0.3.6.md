# Adopt native navigation ownership — kit 0.3.6

Follow [workflow updates](../workflow-updates.md) and the existing context-efficiency policy. For 0.5+, apply the process-decoupling migration separately; these navigation requirements remain. This is a focused input/lifetime correction, not an engine or architecture migration.

1. Assess the installed baseline and project customizations. Inventory active UI input providers, raw input listeners, native callbacks, focus rings, screen/modal coordinators, gameplay gates and transition lifetimes. Trace one physical Move/Submit/Cancel through every handler. Mark each requirement apply/defer/already-adopted from behavior, not version labels.
2. Dry-run/update/check managed standards. Preserve customized routing, tests and templates; do not overwrite an existing coordinator with the example or introduce a second stack. Do not change globals/caches or consuming games without task scope authorizing that action. No OpenSpec reinitialization or historical receipt refresh.
3. Default ordinary menus to native movement/activation. Remove redundant raw handlers narrowly; retain semantic screen intents and existing ViewModels. Choose one Cancel owner and a tested Pause-opening handoff. Preserve custom traversal only where its concrete requirement and native integration are verified for the project's Editor.
4. Apply stack ownership where hierarchical navigation fits. Keep passive overlays and parallel regions separate. Audit focus fallback, top-modal input confinement, binding/resource teardown, reload/reopen, async generation checks and motion cancellation. Retain project-specific layouts, resources and animation behavior. The reference is synchronous and single-panel, not a drop-in animated global router.
5. Extend the existing runtime suite with the [native-input acceptance](../ui-navigation.md#acceptance). Port the relevant fixture cases to the project's actual provider, panel, action maps and lifetime wiring. Prove the ordinary final-focus assertion rejects an injected duplicate router, then remove the fault. Test gameplay gating, held input, keyboard/controller/pointer and target player/device behavior. Report fast kit checks separately from Unity runtime acceptance.
6. Record exact Editor/packages/provider, fresh results, compatibility limits and deferred acceptance. Use the project’s existing implementation record; managed policy adoption alone does not certify the game. Never rewrite historical acceptance to claim the new tests ran.
7. Roll back the scoped migration commit/patch and coupled callback/provider changes together, preserving unrelated authored work. Revalidate the restored input path; do not leave half of a paired ownership change applied.
